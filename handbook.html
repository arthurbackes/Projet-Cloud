Guide de survie du groupe

Construire la boutique dans le Cloud.

SCApp est une boutique en ligne dont l'interface existe déjà. Votre mission est de lui donner un vrai back-end : des données persistantes, des services séparés, du déploiement et la capacité de grandir.

Projet à deux développeursRendu : 23 novembre 2026Node.js + Docker + Azure

La question à garder en tête

Que se passe-t-il si l'utilisateur ferme son navigateur, revient demain ou se connecte depuis un autre appareil ? Les données doivent toujours être là.

Comptes, produits, paniers, achats et logs sont conservés côté serveur. Un navigateur ne doit plus être la seule mémoire de l'application.

Suivez cet ordre : chaque étape donne une base concrète pour la suivante.

Faire tourner la base

Lancer le front-end, le service d'authentification et CouchDB avec Docker. Tester les échanges avec le navigateur et curl.

Construire catalogue, panier et achats

Ajouter l'administration et les images

Protéger l'interface admin, permettre la gestion des produits et envoyer les images vers Azure Storage.

Observer et recommander

Centraliser les logs, mesurer les temps de réponse et créer les vues Map/Reduce qui servent les recommandations.

Déployer et prouver

Assembler les services dans Docker Swarm, tester plusieurs instances, préparer Azure, documenter et présenter les choix.

Le protocole anti-blocage

  1. Contrat avant code : aucune intégration ne commence sans exemple JSON et code d'erreur connu.
  2. Mocks obligatoires : chaque service a une réponse simulée minimale pour que l'autre puisse avancer.
  3. Workflow Git par issue : créer une branche dédiée depuis dev (par exemple feat/auth-couchdb ou fix/cart-total), faire des commits ciblés, pousser la branche, ouvrir une PR vers dev, puis demander une relecture à l'autre membre avant de fusionner. À la fin du sprint, ouvrir une seule PR de dev vers main. Ne jamais travailler directement sur main.
  4. Fallback documenté : si Azure, Swarm ou un service est indisponible, la démo locale et le scénario simulé restent exécutables.
  5. Décisions gelées : les noms de routes, les champs JSON et les ports sont figés le 10 novembre ; les améliorations non essentielles passent après le rendu.

Glossaire express

API REST

Une manière standardisée de demander une action à un service par HTTP. Par exemple : consulter un produit, créer un utilisateur ou modifier un panier.

Microservice

Petit programme indépendant qui s'occupe d'un domaine précis. Il peut être développé, déployé et augmenté séparément des autres.

Conteneur Docker

Environnement emballé qui contient un programme et ses dépendances. Il permet de lancer le même service de manière prévisible sur un ordinateur, une VM ou Azure.

Base NoSQL / document JSON

Base qui stocke des objets souples sous forme de documents JSON plutôt que dans des tables relationnelles classiques.

Stateless

Un service stateless ne garde pas son état de session dans sa mémoire locale. L'état important est stocké dans une base, ce qui facilite l'ajout d'instances.

Élasticité

Capacité à ajouter ou retirer des ressources selon la charge. L'objectif est de servir plus d'utilisateurs sans devoir tout reconstruire.

Map/Reduce

Technique qui parcourt des documents, regroupe les informations utiles et produit des résultats consultables. Ici, elle sert à calculer des recommandations.

API Gateway

Point d'entrée qui reçoit les demandes du front-end et les dirige vers le bon microservice.
